# A11Y · G1: Entry (welcome, sign-in, callback, onboarding, intro, join, invite, offline, goodbye, 404, unconfigured)

Run 2026-11-07 by US-A-A11Y-G1 at `9c703a6` (no app code change since the baselines).

Skills read: `accessibility-audit` (`SKILL.md`; `references/wcag-checklist.md`, `references/common-issues-and-fixes.md`, `references/testing-tools-and-techniques.md`), `accessibility-review` (`SKILL.md`, WCAG 2.1 AA quick reference and output format). Method: accessibility-audit's 5-layer process on every G1 state from `scores.md` "Screens G1":
1. **Automated:** axe-core (`mobile.mjs` `axe(page)`, WCAG 2.0–2.2 A/AA + best practice) on all 22 reachable states in WebKit iPhone 15 and Chromium Pixel 7.
2. **Keyboard:** Tab order from the top of each state, with focus visibility (`:focus-visible` + outline), whether the focused element is in view, and whether something covers it (`elementFromPoint`). WebKit tabs only to form fields (Safari's default "Press Tab to highlight each item" is off), so the full order comes from Chromium. Focus after each action: email → code step, wrong code, "שינוי כתובת", onboarding submit.
3. **Screen reader:** the accessibility tree of each state (Playwright `ariaSnapshot`, `*.aria.txt`) checked against the skill's "What to Listen For" table; live regions listed with their role and content at each step.
4. **Visual:** contrast of every text node on every state in both engines. Background = the pixels under the text box in a shot with all text made transparent, one viewport shot per scroll position (full-page shots change the `dvh` layout in WebKit and gave wrong boxes); foreground = the computed colour blended with its alpha and ancestor opacity. Reported at the median pixel. Then the same for input and checkbox boundaries against the glass (1.4.11). Because Playwright WebKit skips `backdrop-filter: saturate()` and so draws the glass too white, the deciding numbers for glass come from Chromium and the Simulator's Mobile Safari (US-005 set, same code). Text spacing (1.4.12, the skill's bookmarklet values) on welcome with both notices and on the sign-in steps.
5. **Flow:** the sign-in flow by keyboard (Enter in the field submits; the code auto-submits), the onboarding error path, the invite copy action, the join outcomes.

Assumptions and skips: `accessibility-review` takes a Figma URL and points at `CONNECTORS.md` (missing): the input here is the running app, screenshots and code. Neither skill's browser extensions (axe DevTools, WAVE, Lighthouse) are used. axe-core through Playwright does the same job and needs no new dependency (PRD §3.1.7). No real VoiceOver pass: VoiceOver can't be driven in the Simulator with `cliclick`. The accessibility tree stands in for it, and the owner may want a real-device VoiceOver pass before launch. Severity: the skill's Critical/High → P1, Moderate (AA) → P2, Low/best practice → P3. Earlier lenses already filed several a11y problems; they're listed at the end, not filed again.

## Findings

### A11Y-G1-01: Text fields and checkboxes have no visible edge on the glass

- **Screen and state:** sign-in email and code fields, onboarding name field and the three consent checkboxes, intro surname field, invite link field
- **Browser:** webkit-iphone · chromium-pixel · sim-safari (same in all; numbers below)
- **What's wrong:** a field is a white box with a `border-line` (#E6DDD6) edge. On the glass panel the edge measures 1.1–1.2:1 against the glass around it (Safari 1.10:1, Chromium 1.11–1.16:1), and the white fill itself only 1.5–1.6:1 (Safari 1.47:1). On the intro's glass row it's 1.4–1.5:1, and the invite's sand field on the white card is 1.18:1. Nothing else marks where the field is: the label sits above and the placeholder is 2.2:1 (IMP-C-G1-06). People with low vision see a faint pale patch, not a box to tap. The native checkboxes' grey ring is 1.6–2.5:1 on the glass in WebKit and 2.1–3.2:1 in Chromium. A field whose edge you can't see is the skill's 1.4.11 case. The red `aria-invalid` border (4.3–4.6:1) shows the field only once there's an error.
- **Rule it breaks:** `accessibility-audit` · `references/wcag-checklist.md` §3 Non-Text Contrast (1.4.11 AA) · "UI components (buttons, inputs, dropdowns): ≥ 3:1 against adjacent colors"; `accessibility-review` · `SKILL.md` · "1.4.11 Non-text contrast >= 3:1 (UI components, graphics)"
- **Severity:** P2 (AA failure; the label and the tap target still work)
- **Effort:** S (fields) + S (checkboxes)
- **Proposed change:** (1) text fields: `border-stone` instead of `border-line` on the five inputs (`EmailSignIn.tsx`, `auth/CodeInput.tsx`, `Onboarding.tsx`, `Intro.tsx`, `InviteScreen.tsx`), ideally one shared field class next to `buttonClass` in `ui/classes.ts`. Stone is 3.9:1 on the Safari glass and 5.7:1 against the white fill; `aria-invalid:border-urgent` stays. Pair with ELEV-G1-02, so focus draws on the same edge. (2) checkboxes: `appearance-none` box with `border-2 border-stone rounded-sm bg-surface`, `checked:bg-ink checked:border-ink` and a check mark drawn by a CSS mask, keeping `size-6`, the label as the target and `:focus-visible`. Re-measure with `a11y-g1-contrast.py` (≥ 3:1 against the glass in Chromium and Safari).
- **Guardrail:** polish (existing tokens, no token value changes; the field keeps its shape and fill)
- **Screenshot:** `audit/A11Y-G1/signin-email-sim.png`, `audit/A11Y-G1/onboarding-default-chromium.png`, `audit/A11Y-G1/intro-top-sim.png`, `audit/A11Y-G1/invite-link-webkit.png`

### A11Y-G1-05: Focus jumps into the field, so a screen reader skips each step's title and instructions

- **Screen and state:** `/names/sign-in/email` email step (on load) and code step (after "שליחת קוד")
- **Browser:** webkit-iphone · chromium-pixel (accessibility tree and `document.activeElement`)
- **What's wrong:** both fields have `autoFocus`. On the code step focus goes to `#code` with no description (`aria-describedby` is empty until an error). A screen-reader user hears "הקוד מהמייל, שדה טקסט" and nothing else. They don't hear the new title "מה הקוד?", the address the code went to, that it's 6 digits, or "אפשר לבדוק גם בתיקיית הספאם". These are the instructions for the step, and focus has already moved past them. The email step is the same: on load, focus skips the back link, the title and the lead "נשלח קוד בן 6 ספרות לכתובת שלך."
- **Rule it breaks:** `accessibility-audit` · `references/wcag-checklist.md` §6 Labels and Instructions (3.3.2 A) · "Sufficient instructions and examples provided"; `testing-tools-and-techniques.md` What to Listen For · Form field "Email, edit text"; `SKILL.md` Layer 3 · "Are form fields announced with their labels?"
- **Severity:** P3 (the label is announced; the missing part is the step's context)
- **Effort:** XS
- **Proposed change:** `auth/AuthLayout.tsx`: give the lead `id="auth-lead"`. In `EmailSignIn.tsx`, `aria-describedby` on `#email` and on `CodeInput` becomes `"auth-lead"` plus `email-sign-in-error` when there's an error (both ids, error last). Keep the autofocus; no copy change.
- **Guardrail:** polish
- **Screenshot:** `audit/A11Y-G1/signin-code-webkit.aria.txt`, `audit/A11Y-G1/signin-code-webkit.png`

### A11Y-G1-06: Join's outcome is announced by a live region that appears already filled, then read twice

- **Screen and state:** `/names/join/[code]` signed in: "רק רגע, מצטרפים לבחירה" → joined / already a member / expired / error
- **Browser:** webkit-iphone · chromium-pixel (accessibility tree)
- **What's wrong:** each outcome renders a new `<p role="status" class="sr-only">` that already holds the title and lead. The joining spinner's own `role="status"` is a different element, removed at the same moment. Screen readers announce changes to a live region that already exists. A region inserted with its text is often not announced (VoiceOver on iOS is inconsistent), and focus stays on `body`, so the outcome can pass unnoticed. When the person then reads the page, the sr-only copy repeats the heading and lead right after them: "הצטרפת. מעכשיו שמות… / הצטרפת. מעכשיו שמות…" (`join-joined-webkit.aria.txt`).
- **Rule it breaks:** `accessibility-audit` · `references/common-issues-and-fixes.md` §12 Missing Status Messages · "Live region approach — add region first, then inject content"; `wcag-checklist.md` §4 Focus Behavior · "Focus moves to new content when dynamically added"
- **Severity:** P3
- **Effort:** S
- **Proposed change:** `JoinScreen.tsx`: render one `role="status"` sr-only region for every signed-in state (spinner and outcomes), mounted from the first render, and set its text when the outcome lands. Drop the per-outcome sr-only copies, or move focus to the outcome's `h1` (`tabIndex={-1}`) so the title and lead are read once in order. Same pattern as `ResendTimer`'s always-mounted status.
- **Guardrail:** polish
- **Screenshot:** `audit/A11Y-G1/join-joined-webkit.aria.txt`, `audit/A11Y-G1/join-expired-webkit.aria.txt`, `audit/A11Y-G1/join-joined-webkit.png`

- **Screen and state:** `/names/invite`, tap "העתקת הקישור" (and "שליחת קישור הזמנה" where it falls back to copying)

Check that `ToastRegion` announces a repeated "הקישור הועתק" on a second tap. If it doesn't, keep the local region and drop the toast's text from the accessibility tree instead.
- **Guardrail:** polish

## Considered and not filed

- **The terms checkbox's name is the whole sentence with "(נפתח בכרטיסייה חדשה)" twice.** It's long, but it contains the visible label (2.5.3 Label in Name), and shortening it would drop the visible words or the new-tab warning. Triage may revisit it with PRO-G1-02, which restructures the same label.
- **Live regions present at load with text** (`ClosedNotice`, `ExpiredNotice`, goodbye's status): on a page load the screen reader reads them in order; nothing changes later, so nothing is lost.
- **`ConnectionNote` is a `display: contents` live region.** It is exposed as `status` in the accessibility tree in both engines (snapshots), so current WebKit and Chromium keep its role. The offline announcement itself wasn't heard (no VoiceOver), so the QA cycles should listen for it on a device.
- **Disabled controls under 4.5:1** ("שליחה חוזרת" 1.7–2.8:1, disabled primary pills 3.0–3.4:1): disabled components are exempt from 1.4.3. Their look is ELEV-G1-01.
- **Intro lead in Chromium (3.8:1 at the median)** is a sampling artefact of the photo's fold under the second line. In Safari it's 5.9–6.4:1, and WebKit gives 5.4:1.
